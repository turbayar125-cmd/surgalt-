# Сургалтын бүртгэлийн систем — otpclicenses.mn

Ажилтнуудын сургалтын хүчинтэй хугацааг хянаж, дуусахаас өмнө имэйлээр сануулдаг систем.

**Боломжууд:** хянах самбар · **Алба** цэс (баг бүрийн бүтэц org chart-аар) · ажилтны профайл (зураг, удирдлага, ажилд орсон огноо) · сургалтын бүртгэл, сунгалт, түүх · **Excel матриц оруулах** (долоо хоног бүр) · өдөр бүр автомат имэйл сануулга.

> **Одоогийн байдал:** `index.html` дахь `CONFIG` хоосон байгаа тул сайт **демо горимд** ажиллаж байна — жишээ өгөгдөл харуулна, оруулсан зүйл хадгалагдахгүй. Доорх 1–5 алхмыг хийснээр жинхэнээр ажиллана.

| Үйлчилгээ | Юунд | Үнэгүй хязгаар |
|---|---|---|
| **Supabase** | Өгөгдлийн сан, нэвтрэлт, профайл зураг, өдөр бүрийн сануулга | 500 MB сан, 1 GB зураг. 7 хоног огт ашиглаагүй бол түр зогсоно (dashboard-оос нэг товчоор асаана) |
| **Resend** | Имэйл илгээх | Өдөрт 100, сард 3,000 имэйл |
| **GitHub Pages** | `otpclicenses.mn` дээр байршуулах | ✅ Хийгдсэн |

Файлууд: `index.html` (апп), `setup.sql` (сан), `CNAME` (домэйн).

---

## 1. Supabase project үүсгэх (5 мин)
1. https://supabase.com → **Start your project** → GitHub-аараа нэвтэрнэ.
2. **New project** → нэр: `surgalt`, нууц үг өгнө, Region: **Singapore**.
3. 1–2 минут хүлээнэ.

## 2. Өгөгдлийн сан үүсгэх
1. Зүүн цэс → **SQL Editor** → **New query**.
2. Энэ repo-гийн `setup.sql` файлыг нээгээд бүх агуулгыг хуулж буулгана → **Run**.
3. "Success" гарвал болсон. 8 алба (BP, MT, CP, QAQC, WH, HSE, Administration, HR) автоматаар үүснэ.

Дахин ажиллуулахад аюулгүй — байгаа өгөгдлийг устгахгүй. Дараа шинэчлэл гарвал мөн адил ажиллуулна.

## 3. Нэвтрэх эрх
1. **Authentication → Sign In / Providers → Email**: **Allow new users to sign up**-ийг **унтраана**.
2. **Authentication → Users → Add user → Create new user**: хүний нөөцийн ажилтны имэйл, нууц үг, **Auto Confirm User** чагтална.

## 4. Апп-ыг Supabase-тэй холбох
1. **Project Settings → API** хэсгээс **Project URL** болон **anon public** key-г хуулна.
2. GitHub дээр `index.html` → ✏️ (Edit) → доорх мөрүүдийг бөглөөд **Commit changes**:
   ```js
   const CONFIG = {
     SUPABASE_URL: 'https://abcdxyz.supabase.co',
     SUPABASE_ANON_KEY: 'eyJhbGciOi...'
   };
   ```
   anon key-г нийтэд харуулахад аюулгүй — эрхийг сангийн RLS хамгаална. (Эсвэл утгуудаа Claude-д өгөөд оруулуулж болно.)

## 5. Имэйл илгээх (Resend)
1. https://resend.com → бүртгүүлнэ → **Domains → Add Domain** → `otpclicenses.mn`.
2. Resend-ийн өгсөн DNS бичлэгүүдийг (TXT, MX) домэйны DNS удирдлагад **яг ижилхэн** нэмнэ → **Verify**.
3. **API Keys → Create API Key** → `re_...` түлхүүрийг хуулна.
4. Supabase → SQL Editor дээр (өөрийн түлхүүрээр солиод) ажиллуулна:
   ```sql
   select vault.create_secret('re_ТАНЫ_ТҮЛХҮҮР', 'resend_api_key');
   ```

## 6. Домэйн: www хаягийг засах
GitHub → Settings → Pages дээр *"www.otpclicenses.mn is improperly configured"* гэж гарч байгаа. Домэйны DNS удирдлагад:
- `www` хостын **A** бичлэг(үүд)-ийг **устгана**.
- Оронд нь `www` хостод **CNAME** бичлэг нэмнэ, утга: `turbayar125-cmd.github.io`
- `@` хостын 4 A бичлэг (185.199.108–111.153) хэвээр үлдэнэ.

Хэдэн минутаас хэдэн цагийн дараа **Check again** → дараа нь **Enforce HTTPS**-ийг асаана.

## Ашиглах

### Excel матриц оруулах (долоо хоног бүр)
**Хянах самбар**, **Сургалтын бүртгэл** эсвэл **Тохиргоо** хуудасны **Excel оруулах** товч, эсвэл Тохиргоо доорх талбар руу файлаа чирж оруулна. `.xlsx`, `.xls`, `.csv` уншина.

- Гарчгийн мөрийг (Код, Овог нэр, Алба, Албан тушаал…) автоматаар олно; дээрх гарчиг, тайлбар мөрүүдийг алгасна.
- Сургалт бүрийн багананд огноо байвал сургалт гэж танина. Нүдэнд **хамрагдсан** эсвэл **дуусах** огноо байгааг оруулахдаа сонгоно (системийн таамаг харагдана).
- 2 мөр гарчигтай матриц (сургалтын нэрийн доор "Хамрагдсан / Дуусах / Гэрчилгээ") болон жагсаалт хэлбэрийг (мөр бүр нэг сургалт) уншина.
- Ажилтныг **Код**-оор, байхгүй бол **нэрээр** нь таньдаг. Системд байхгүй хүнийг шинээр нэмнэ (сонголттой).
- "BP" гэх мэт бүлгийн гарчигтай мөрийн доорх хүмүүст алба автоматаар оноогдоно.
- **Удирдлага** багана (удирдлагын нэр эсвэл код) байвал Алба цэсний бүтэц автоматаар зурагдана.
- Оруулахаас өмнө урьдчилан харуулна. **Ижил файлыг дахин оруулахад давхардахгүй** — зөвхөн шинэ огноотой бичлэг нэмэгдэж, хуучин нь түүхэнд хадгалагдана.
- Шинэ сургалтын нэр гарвал хүчинтэй хугацааг (сараар) тэнд нь оруулна.

### Алба ба бүтэц
**Алба** цэс → баг дээр дарахад удирдлагаас эхэлсэн бүтэц харагдана. Карт бүрийн зүүн захын өнгө тухайн хүний сургалтын төлөв (ногоон/шар/улаан/саарал). Хүн дээр дарвал профайл нээгдэнэ. Удирдлагыг профайл → **Мэдээлэл засах** → **Шууд удирдлага**-аас эсвэл Excel-ийн "Удирдлага" баганаар тохируулна.

### Сануулга
- Өдөр бүр **09:00** (Улаанбаатар) автоматаар илгээнэ. Анхдагч: дуусахаас 30, 14, 7, 1 хоногийн өмнө ба дуусах өдөр — тус бүр нэг удаа.
- Ажилтанд очиж, хүний нөөцийн имэйлд хуулбар очно. Имэйлгүй бол зөвхөн хүний нөөцөд.
- Ажлаас гарсан ажилтны **Идэвхтэй** тэмдгийг арилгавал сануулга очихгүй, түүх хадгалагдана.

### Албадын бүтэц (org chart)
**Алба** цэс бүх албадын бүтцийг нэг дор харуулна. Алба → **Нээх / засах**:
- **Загвараар үүсгэх**: QAQC, BP, WH, CP, HR, MT-д бэлэн загвар бий; албан тушаал нь таарсан хүмүүсийг автоматаар байрлуулна.
- Хүнийг чирж хайрцаг руу оруулна (хоёр хүн байр солино), **+** дарж доор нь хайрцаг нэмнэ, **⋯** дарж нэр солих / хүн сонгох / устгана.
- Энэ засварыг **нэвтэрсэн бүх хүн** хийж чадна (ажилтан, сургалтын мэдээлэл зөвхөн админд).

### Эрх: админ ба харах
- **Админ** (Тохиргоо → "Админ эрхтэй хүмүүс" жагсаалтад байгаа имэйл): бүх мэдээлэл засна, Excel оруулна, зураг солино.
- **Бусад нэвтэрсэн хүн**: зөвхөн харна. Засах товчнууд харагдахгүй, сан нь өөрөө ч засварыг хориглоно.
- Шинэ хүнд нэвтрэх эрх өгөх: Supabase → Authentication → Users → **Add user** (Auto Confirm). Админ болгох бол сайтын Тохиргоо хэсэгт имэйлийг нь нэмнэ.

## Асуудал гарвал (SQL Editor дээр)
```sql
select status_code, content, created from net._http_response order by created desc limit 5;      -- Resend-ийн хариу
select status, return_message, start_time from cron.job_run_details order by start_time desc limit 5; -- өдөр бүрийн ажил
```
- `403` / "domain is not verified" → Resend дээр домэйн баталгаажаагүй (5-р алхам).
- "Resend API түлхүүр Vault-д алга" → 5.4-р алхам.
- "Өгөгдөл ачаалж чадсангүй" → 2-р алхам эсвэл CONFIG-ийн утгыг шалгана.
